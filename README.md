# 상담 후속 업무 보드

상담 메모에서 업무 확정과 알림 전달까지. 상담이 끝나면 설계사가 약속과 기한을 확인하고, 운영자는 알림이 어느 단계에서 멈췄는지 추적할 수 있는 개인 프로젝트입니다.

[포트폴리오 PDF](docs/portfolio.pdf) · [업무 보드 시연 화면](docs/screens/01-confirm.png) · [전달 복구 화면](docs/screens/03-recovered.png)

## 1분 시연

1. 저장소를 내려받아 `src/main/resources/static/index.html`을 Chrome에서 엽니다. 샘플은 가상의 상담입니다.
2. **후속 업무 초안 만들기**를 누릅니다. 두 후보의 근거 문장과 기한을 확인하고 각각 확정합니다. 서류 업무 하나를 완료 처리합니다.
3. **전달 통계 → 수신 직후 워커 중단**을 누르면 수신함 반영은 1, 완료 확인 대기도 1입니다. **다음 워커 처리**를 누르면 기존 수신을 확인하고 대기가 0으로 줄어듭니다.
4. 한 번 더 처리하여 업무 2건, 업무 완료 1건, 수신 2건을 대조합니다. 유형별 완료율은 설계사가 완료한 업무만 셉니다.

브라우저 시연은 계정별 로컬 저장소를 사용하며 임대 만료 대기를 생략합니다. API 모드는 인증된 설계사와 PostgreSQL을 사용합니다.

## 구현

| 영역 | 기술과 선택 |
| --- | --- |
| 화면 | React 18, JavaScript. 메모를 문장별로 나누고 근거와 날짜를 나란히 보여 줍니다. |
| API | Kotlin, JDK 21, Spring Boot 3.5, Spring Security, JDBC. 요청 키는 설계사별로 고유합니다. 같은 키·같은 내용은 기존 ID를 반환하고 내용이 달라지면 409를 반환합니다. |
| 영속화 | PostgreSQL 16. 업무, 전달할 알림, 접수 이력을 한 트랜잭션에 기록합니다. |
| 워커 인수 | 워커 2개가 SKIP LOCKED로 대기 행을 선택합니다. DB 시각 기준 30초간 임대하며 인수 때마다 세대 번호를 올립니다. 늦게 돌아온 이전 워커의 완료 갱신은 소유자·세대 조건에서 걸러집니다. |
| 수신 중복 처리 | 수신함은 업무 ID를 기본키로 사용합니다. 수신 기록과 완료 확인을 별도 커밋해 사이에 중단될 수 있는 구간을 재현합니다. 실제 외부 발송사를 붙이려면 수신 측에도 동일 키 처리 또는 결과 조회가 필요합니다. |
| AI 보조 | 브라우저가 메모를 신호로 변환합니다. 선택형 Ollama 분류기는 허용된 신호와 후보만 받습니다. 시간 초과·형식 오류 시 규칙 초안을 제공하며 최종 저장은 사용자 확정 후 진행합니다. |
| 통계 | 현재 설계사의 전체 업무를 기준으로 업무 완료율과 유형별 건수, 미수신·수신 후 확인 대기를 계산합니다. 분모가 0이면 전체 완료율은 대시로 표시합니다. |

통계의 기준은 업무 ID입니다. 워커 재시도는 처리 이력에만 추가합니다. **접수 = 미수신 + 수신**, **수신 = 완료 확인 + 확인 대기**를 대조할 수 있습니다. 현 버전은 단일 PostgreSQL과 전체 목록 기반 집계를 사용합니다. DB 자체 장애 전환, 외부 문자 발송, 대규모 집계 성능은 별도 검증 대상입니다.

## 서버 실행

Docker Compose 환경에서 `.env.example`을 `.env`로 복사하고 서로 다른 DB·설계사 비밀번호 세 개를 설정합니다. 루프백에서만 접근하는 개발 구성입니다.

```sh
docker compose up --build -d
```

http://127.0.0.1:8080 에서 advisor-a 또는 advisor-b로 로그인합니다. 스키마는 PostgreSQL 볼륨 최초 초기화 시 생성됩니다. 로컬 모델을 사용할 때는 컨테이너에서 접근할 수 있는 OLLAMA_URL 및 설치한 OLLAMA_MODEL을 설정합니다.

## 검증

- Node 22+에서 `node --test tests/logic.test.cjs`로 초안, 날짜, 멱등성, 통계, 인수 및 계정 분리를 확인합니다.
- Chrome과 Playwright가 있는 환경에서 `node tests/browser.cjs`로 시연 화면의 버튼을 조작하고 캡처를 갱신합니다.
- 서버가 준비되면 실행 셸에도 ADVISOR_PASSWORD와 SECOND_PASSWORD를 설정하고 `python tests/server_smoke.py`를 실행합니다. 동시 요청 4회, 충돌, 다른 계정의 접근, DB 기반 전달 완료를 검증합니다.
- 워커 강제 중단 검증은 별도의 비어 있는 테스트 스택에서 실행합니다. 두 워커를 ACK_DELAY_MS=20000으로 기동한 뒤 `python tests/server_smoke.py --failover`를 실행합니다. A의 수신 기록을 관측한 후 A를 종료하고 B를 시작해 동일 업무를 인수하는지 판정합니다. 종료 시 두 워커를 다시 시작합니다.
- k6 스크립트 `k6 run tests/load.js`는 기본 초당 5개 업무를 1분간 접수하고 같은 키로 재요청합니다. RATE·DURATION으로 변경할 수 있습니다. 통과 기준은 응답 ID 일치, 실패 요청 및 누락된 반복 0입니다. 설정값은 시험 목표입니다.

현재 확인한 범위는 Node 단위 검증과 Chrome 브라우저 시연입니다. Spring 빌드, PostgreSQL 통합 실행, 실제 워커 프로세스 절체, k6 성능 수치 및 외부 모델 호출은 미검증입니다.
